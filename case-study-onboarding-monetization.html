User onboarding and monetization dashboard

SQL analysis in Google BigQuery and a Looker Studio dashboard for WYZR Friends, a live product built by my company.

Role
Analysis, SQL and dashboard build
Client type
Internal product team
Tools
Google BigQuery (SQL), Looker Studio
Outcome
Partial answer; limited by the absence of real monetization data

Context

The project manager of WYZR Friends asked for an analysis of user onboarding and monetization. WYZR Friends is a live product built by my company, so the work used real user data, with the team’s permission.

[Add the exact question the project manager asked, in one sentence.]

My role

I wrote the SQL queries in Google BigQuery and built the dashboard in Looker Studio. I framed the business questions the queries answer, defined the metrics, made the data-governance decisions described below, and validated the outputs.

Approach

Rebuilding the age field

The stored age field was about 40% empty, and its bands overlapped. I recalculated age from date of birth instead. [VERIFY]

Decision

Recalculating from date of birth gives one consistent definition of age, rather than patching a field with gaps and overlapping bands.

Setting a minimum segment size

Segments with fewer than 50 users were excluded. Rates from groups that small were too unstable to compare. [VERIFY]

Trade-off

Some small groups drop out of the view. The rates that remain can be compared with each other.

Modelling revenue as scenarios Simulated

Monetization data was not available to me, so the revenue component is a simulation. A Looker Studio parameter switches the estimate between conservative, base and optimistic scenarios. [VERIFY]

Decision

Three labelled scenarios show a range and keep the assumption visible. A single simulated number would read as a forecast.

Data governance and constraints

  • Permission. All permissions were obtained from the team before the data was used.
  • Personal data. Email and phone-number fields were deliberately excluded.
  • Volumes. All user counts are scaled with multipliers. No real counts appear on this page.
  • Revenue. The revenue component is a simulation Simulated, because monetization data was not available to me.
  • Access. The live dashboard is not linked or embedded. It contains production queries and carries risk to the client.

Outcome

The analysis answered part of the business question but produced limited actionable results. The main reason was the absence of real monetization data: the onboarding analysis rests on real, scaled user data, while the revenue side can only show simulated scenarios.

What I learned

Most of the work happened before the first query was written: deciding which fields could be trusted, which could be used at all, and which segments were large enough to report. An analysis is only as strong as the data it is allowed to see.
